# 新手详细说明注释器

把代码改成「自学友好」：读者不用先懂框架，也能顺着注释走完主链路。

参考范本（风格与粒度对齐它）：`src/mem0/mem0-redis-mem0-agent.mjs`  
片段对照见 [examples.md](examples.md)

## 何时启用

- 用户明确要求加注释 / 新手导读 / 详细说明
- 为练习脚本、demo、教学向文件补注释
- 用户说「按 beginner-annotator」或 `@beginner-annotator`

**不要**对生产核心库、第三方包、或用户未点名的文件主动大面积加注释。

## 注释原则

1. **中文**为主；专有名词可保留英文（Redis、Mem0、TTL、`invoke`）。
2. **解释「干什么 + 为什么」**，少复述语法本身（别写「这是一个函数」）。
3. **类比**优先：身份证号 / 小票号、草稿纸、安检门、门牌号等生活场景。
4. **执行序号**标清先后：主链路、函数内步骤、模块装配顺序。
5. **新手易混点**单独点出（例如「检索结果不会自动进模型，必须放进 messages」）。
6. **不改行为**：只加注释与必要空行；不重构、不改逻辑、不删功能代码。
7. **密度适中**：复杂处详细，显而易见的一行赋值用一行短注释即可。

## 必备结构（按文件从上到下）

### 1. 文件头「新手导读」

文件顶部用块注释，固定标题：

```js
/**
 * ============================================================================
 * 新手导读：这份文件在干什么？
 * ============================================================================
 *
 * （用白话讲目标 + 核心概念）
 *
 * （可选：ASCII 分区表 / 数据流）
 *
 * ----------------------------------------------------------------------------
 * 主流程怎么走？（对应核心函数名）
 * ----------------------------------------------------------------------------
 *  1. …
 *  2. …
 *  …
 *
 * 阅读建议：先看 XXX，再看 YYY。
 * ============================================================================
 */
```

导读必须包含：

- 一句话目标
- 关键概念对比（若有多层存储/角色）
- **为什么这样设计**（各 1～3 条，避免只堆概念）
- **带序号的主数据流**（对应真正的入口函数）
- **阅读顺序建议**

### 2. 分区横幅

大块逻辑用分隔注释：

```js
// ============================================================================
// 配置：……（一句人话）
// ============================================================================
```

或装配阶段用序号横幅：

```js
// ---------- 5. 主对话模型（真正陪你聊天的那个） ----------
```

同一文件内序号连续、与导读里的主流程呼应。

### 3. 声明 / 函数 / 方法注释

复杂符号用 `/** … */`：

- 它是什么、谁会调用
- 关键参数/返回值含义（门牌号、TTL、schema 字段等）
- **为什么**需要它（防污染、防重复、省 token…）
- 多步逻辑写 **步骤：1. 2. 3.**

简单常量可用单行 `/** … */`。

### 4. 行内执行序号

函数体内关键步骤用 `// 1.` `// 2.` 或 `// 9.1` 子序号，与上方「步骤」列表一致：

```js
async function example() {
    // 1. 取出历史
    // 2. 检索记忆
    // 3. 调用模型
}
```

分支命令、REPL 循环等用 `9.1` / `9.2` 这种「父序号.子序号」。

### 5. 文末动手实验（可选，适合 demo）

用块注释给出可复制的体验路径与**预期结果**，帮助新手验证理解。见范本文件末尾。

## 写法清单（每次注释时自检）

- [ ] 有「新手导读」且含带序号主流程
- [ ] 模块/阶段有横幅；装配处有连续执行序号
- [ ] 复杂函数有「步骤」列表，且行内序号对齐
- [ ] 至少点出 1～2 个「新手易混点」或「为什么」
- [ ] 未改运行逻辑；注释为中文白话 + 必要英文术语
- [ ] 没有为 `i++`、`console.log` 这类显而易见处灌水

## 禁止事项

- 不要英文长篇 doc，除非用户要求
- 不要只贴 API 文档原文而不解释本文件里怎么用
- 不要把注释写成第二份实现（伪代码复述整段代码）
- 不要发明与代码不符的执行顺序

## 输出方式

1. 直接改目标文件，写入注释
2. 改完后用几句话告诉用户：导读在哪、主流程序号对应哪个函数、建议从哪读起
